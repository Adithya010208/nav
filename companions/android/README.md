# NAV Android companion — source preview

This is a preview, not a finished device release. `assembleDebug`, `lintDebug` and debug APK signature verification pass. A preview APK is available in the task outputs as `nav-android-preview.apk`; actual device acceptance checks are outstanding. It opens the private NAV site in the system browser and offers an optional local notice inbox. It contains no WhatsApp outgoing action, reply, cancellation, accessibility service, network ingestion, or account credential handling.

Preview 0.3 adds an opt-in daily study reminder. Choose a phone-local time, press Enable daily study reminder, then grant Android's notification permission if prompted. Test NAV notification sends a generic local notification. Disable cancels NAV's own alarm and daily notification. Nothing enables itself during install. Reminders use Android inexact alarms, can be delayed by battery restrictions, and stop after force-stop until the app is opened again. Boot, clock/time-zone changes and app upgrades reschedule an enabled reminder. The local time is independent of the website's plan and does not automatically mirror task deadlines. This does not replace cloud deadline push delivery.

Eight pure Java schedule checks cover next-day/year rollover, India time, DST gaps/repeated hours and invalid times (`StudyScheduleTest.java`). The Android test APK also includes isolated inexact-alarm registration/cancellation checks with a no-op receiver action. Preview 0.3 still needs actual notification permission, delivery/sound, disable and closed-app device acceptance checks.

Capture is off by default. Save one exact group title, then explicitly grant NAV notification access in Android Settings. Only `com.whatsapp` group MessagingStyle notifications with that exact title pass. Direct chats, other packages, title variations, empty/oversized text and messages older than 24 hours fail closed. The local inbox deduplicates text/timestamp pairs, retains at most 100 messages / 100,000 characters, and excludes notices older than seven days. Changing group or disconnecting clears the inbox. Android backups are disabled.

Android notification access can expose notifications broadly to a service: the filter runs before retention. No old history, attachments, muted notifications or guaranteed complete group stream is available. Duplicate group titles cannot uniquely identify a WhatsApp group; select a uniquely named group. Review notices before manually importing them into NAV. Automatic cloud ingestion and native reminders are pending.

Build requirements: Android SDK platform 36, AGP 9.4.0, Gradle 9.6.0 and JDK 17 or newer. From this directory with a configured SDK, run `gradle :app:assembleDebug`. No signing credentials are included. Release requires a signed package and actual device checks for consent, cross-group rejection, revocation, privacy, app restart, and browser sign-in.

The pure Java filter can be tested without Android SDK by compiling `SourceFilter.java` with `tests/SourceFilterTest.java`, then running `app.nav.companion.SourceFilterTest`. That test does not validate Android notification delivery or the APK.

Preview 0.2.0 was installed and cold-launched on a real Android 16 phone. The test APK's `app.nav.companion.InboxChecks` instrumentation passed 12 filtering/deduplication/retention checks using synthetic Notification objects and a separate test preference store. It never posts messages or changes the real college inbox. Build with `:app:assembleDebugAndroidTest`, install the main and test APKs, and run `adb shell am instrument -w app.nav.companion.test/app.nav.companion.InboxChecks`. A PASS result validates those fixtures, not actual WhatsApp delivery or cloud ingestion.

Device checks can be run with check-device.ps1 -Adb <absolute-adb-path> -Install. It requires exactly one authorized phone (or -Serial), upgrades the main app without clearing data, runs all 18 isolated fixtures, and removes only the test package afterward. It never grants OS permissions. Without -Install it tests the already installed main app. Real permission, sound, closed-app notification and approved-group receipt remain manual acceptance checks.

Preview 0.4 offers Export captured notices through Android's system file picker, after explicit confirmation. It exports the current approved group and bounded recent notice text, without network or WhatsApp write access. In the signed-in NAV College inbox, choose the JSON file, inspect the preview and Save reviewed notices. Group names must exactly match the website setting. Delete exported files after use. This manual transfer preserves original times and skips duplicates; it does not provide unattended cloud synchronization. Actual phone file-picker acceptance is still pending.

Preview 0.5 adds opt-in private cloud sync after secure USB provisioning. The app now has Internet/network-state permissions for a fixed NAV endpoint. Credentials are encrypted using AndroidKeyStore AES-GCM; no secret is embedded in the APK. Setup remains off until Enable captured-notice cloud sync is confirmed. Android JobScheduler handles network availability, retries and periodic delivery; delay is possible. Disabling cancels jobs; deleting local credentials does not revoke the server capability, which can be revoked under NAV Settings → Connected phones. The one-time USB staging file is removed after encryption. 24 isolated real-device fixtures passed, including storage tamper rejection and group/retention filtering. Actual approved-group cloud receipt still needs end-to-end acceptance.

Preview 0.6 preparation replaces the private Site service credential with a single append-only NAV device credential and a fixed dedicated managed inbox URL. It rejects old service-token setups and arbitrary relay destinations. No Site bearer or Supabase project secret is accepted by the phone or USB setup tool. The upload success message distinguishes queued receipt from website import; open NAV to consume queued notices. Provisioning and production use remain blocked until managed inbox deployment and end-to-end checks. The prepared instrumentation now has 28 checks; this does not claim they have run on a device. Earlier versions and device results above are historical evidence.
